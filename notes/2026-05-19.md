## 1. What Are Embeddings?

An **embedding** is a dense numerical vector that represents a piece of text (or image, audio, etc.) in a high-dimensional space. The idea is that semantically similar content maps to nearby points in that space — a concept called the **distributional hypothesis**: words and sentences that appear in similar contexts have similar meanings.

```
"UAE equity fund"     → [0.12, -0.87, 0.34, 0.05, ...]   # 1536-dim vector
"Abu Dhabi stock ETF" → [0.11, -0.85, 0.33, 0.06, ...]   # very close!
"chocolate cake"      → [-0.54, 0.22, -0.71, 0.88, ...]  # far away
```

Under the hood, embeddings are learned by a neural network (often a transformer) trained on massive text corpora. The network learns to encode *meaning* into position in vector space.

### Why Do We Need Embeddings?

Computers can't directly compare text for meaning — they only understand numbers. Embeddings solve this by converting text into vectors where **arithmetic on numbers corresponds to operations on meaning**.

| Problem | Without Embeddings | With Embeddings |
|---------|-------------------|-----------------|
| "Is 'car' similar to 'vehicle'?" | Exact string match fails | High cosine similarity ✅ |
| Find semantically related docs | Keyword search (brittle) | Vector nearest-neighbour ✅ |
| Cluster 10,000 customer complaints | Impossible without labels | k-means on embeddings ✅ |
| Recommend similar mutual funds | Rule-based logic | Nearest neighbours in vector space ✅ |

## 2. Similarity — How Vectors Capture Meaning Numerically

### Same Words, Different Meanings — Handled

Traditional keyword matching fails on synonyms. Embeddings capture paraphrase:

```
"bond yield" ↔ "fixed income return"   → high similarity (same concept)
"bond"        ↔ "James Bond"           → lower similarity (different context)
```

Both "bond yield" and "fixed income return" land near each other in vector space because they co-occur with the same surrounding vocabulary in training data.

### Distance Between Embeddings

Two main distance metrics used in practice:

#### Cosine Similarity (most common for text)
Measures the **angle** between two vectors. Range: −1 (opposite) to 1 (identical). Ignores magnitude — only cares about direction.

```python
import numpy as np

def cosine_similarity(a: list[float], b: list[float]) -> float:
    a, b = np.array(a), np.array(b)
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

vec_a = [0.12, -0.87, 0.34]   # "UAE equity fund"
vec_b = [0.11, -0.85, 0.33]   # "Abu Dhabi stock ETF"
vec_c = [-0.54, 0.22, -0.71]  # "chocolate cake"

print(cosine_similarity(vec_a, vec_b))  # ~0.999  — very similar
print(cosine_similarity(vec_a, vec_c))  # ~-0.92  — very different
```

#### Euclidean Distance (L2)
Measures straight-line distance between two points. Sensitive to magnitude. Common in clustering (e.g. k-means).

```python
def euclidean_distance(a: list[float], b: list[float]) -> float:
    a, b = np.array(a), np.array(b)
    return float(np.linalg.norm(a - b))
```

| Metric | Formula | Range | Use when |
|--------|---------|-------|----------|
| Cosine similarity | `dot(a,b) / (‖a‖·‖b‖)` | −1 to 1 (higher = more similar) | Text similarity, semantic search |
| Euclidean (L2) | `‖a − b‖` | 0 to ∞ (lower = more similar) | Clustering, anomaly detection |
| Dot product | `dot(a,b)` | −∞ to ∞ | When vectors are already normalised (= cosine) |

> **Rule of thumb:** Use cosine similarity for text embeddings. Qdrant, Pinecone, and most vector DBs default to cosine or dot product.

## 3. Embedding Applications

### 3.1 Semantic Search

Find documents that *mean* the same thing as a query, not just share the same words.

```python
from openai import OpenAI

client = OpenAI()

def embed(text: str) -> list[float]:
    return client.embeddings.create(
        input=text, model="text-embedding-3-small"
    ).data[0].embedding

# Corpus of fund descriptions
docs = [
    "ENBD Islamic Equity Fund invests in Shariah-compliant UAE equities.",
    "Franklin UAE Bond Fund provides exposure to UAE fixed income.",
    "Emirates MENA Growth Fund targets high-growth companies across the Middle East.",
]

doc_embeddings = [embed(d) for d in docs]

# Query — note: different wording, same intent
query = "Shariah compliant stock fund"
query_emb = embed(query)

# Score each doc
scores = [cosine_similarity(query_emb, d) for d in doc_embeddings]
best = docs[scores.index(max(scores))]
print(f"Best match: {best}")   # → ENBD Islamic Equity Fund ✅
```

### 3.3 Recommendations

"You looked at X — here are similar items."

```python
def recommend(query_text: str, corpus: list[str], top_k: int = 3) -> list[str]:
    query_emb = embed(query_text)
    scored = [(cosine_similarity(query_emb, embed(c)), c) for c in corpus]
    scored.sort(reverse=True)
    return [text for _, text in scored[:top_k]]

fund_universe = [
    "ENBD Islamic Equity Fund",
    "Emirates MENA Growth Fund",
    "Franklin UAE Bond Fund",
    "ADCB Fixed Income Fund",
    "Algebra Shariah Equity Fund",
]

print(recommend("Islamic stock fund", fund_universe))
# → ['ENBD Islamic Equity Fund', 'Algebra Shariah Equity Fund', 'Emirates MENA Growth Fund']
```

### 3.4 Anomaly Detection

Detect items that don't fit the expected pattern — their embeddings are far from the cluster centre.

```python
from sklearn.metrics.pairwise import cosine_similarity as sk_cosine
import numpy as np

fund_descriptions = [
    "Invests in UAE equities with a focus on dividend yield.",
    "Shariah-compliant fund tracking UAE blue-chip companies.",
    "Focuses on GCC equities and real estate investment trusts.",
    "BUY NOW! Get rich quick with guaranteed 500% returns!",   # ← anomaly
    "Diversified exposure to MENA equity markets.",
]

embeddings = np.array([embed(d) for d in fund_descriptions])
centroid = embeddings.mean(axis=0, keepdims=True)

# Cosine distance from centroid (1 - similarity)
similarities = sk_cosine(embeddings, centroid).flatten()
anomaly_idx = similarities.argmin()
print(f"Anomaly detected: {fund_descriptions[anomaly_idx]}")
# → "BUY NOW! Get rich quick..."
```

### 3.5 Diversity Measurement

Ensure a selected set of items covers a wide range of topics (e.g. picking 5 representative fund descriptions from a pool of 100).

```python
def max_marginal_relevance(
    query_emb: list[float],
    candidate_embs: list[list[float]],
    top_k: int = 5,
    lambda_mult: float = 0.5,
) -> list[int]:
    """
    Select top_k candidates that are relevant to query AND diverse among themselves.
    lambda_mult=1.0 → pure relevance; lambda_mult=0.0 → pure diversity
    """
    selected: list[int] = []
    candidates = list(range(len(candidate_embs)))

    for _ in range(top_k):
        best_score, best_idx = -float("inf"), -1
        for i in candidates:
            relevance = cosine_similarity(query_emb, candidate_embs[i])
            if selected:
                redundancy = max(
                    cosine_similarity(candidate_embs[i], candidate_embs[j])
                    for j in selected
                )
            else:
                redundancy = 0.0
            score = lambda_mult * relevance - (1 - lambda_mult) * redundancy
            if score > best_score:
                best_score, best_idx = score, i
        selected.append(best_idx)
        candidates.remove(best_idx)

    return selected
```

> MMR (Max Marginal Relevance) is built into LangChain's vector store retrievers: `retriever = vectorstore.as_retriever(search_type="mmr")`.

### 3.6 Classification

Use embedding similarity to a set of class label descriptions — no training required (zero-shot classification).

```python
# Zero-shot classification using embedding similarity
categories = {
    "equity":       "stocks, shares, equity fund, dividend",
    "fixed_income": "bond, sukuk, fixed income, debt fund",
    "money_market": "money market, short-term, liquidity fund",
}

category_embeddings = {k: embed(v) for k, v in categories.items()}

def classify_fund(description: str) -> str:
    emb = embed(description)
    scores = {k: cosine_similarity(emb, v) for k, v in category_embeddings.items()}
    return max(scores, key=scores.get)

print(classify_fund("ENBD Shariah Equity Fund"))   # → equity
print(classify_fund("Franklin UAE Sukuk Fund"))    # → fixed_income
```

## 4. Choosing an Embedding Model — Decision Factors

There is no single "best" embedding model. Choose based on the factors below.

### Key Decision Factors

| Factor | What to Consider |
|--------|-----------------|
| **Task type** | Retrieval (asymmetric: query vs doc) vs similarity (symmetric: doc vs doc) — different models optimise for each |
| **Domain** | General English vs finance/legal/medical — domain-specific models outperform on specialised text |
| **Language** | English-only vs multilingual (Arabic + English for UAE use cases) |
| **Dimensionality** | Higher dim = more expressive but slower retrieval and more storage. 1536-dim for OpenAI, 768-dim for many open-source |
| **Context length** | How long are your documents? Some models cap at 512 tokens, others at 8192 |
| **Latency & throughput** | Cloud API (easy, slower, paid) vs local model (setup cost, faster at scale, free) |
| **Cost** | Per-token pricing for cloud APIs vs one-time GPU cost for self-hosted |
| **Privacy** | Sending customer data to an external API may violate compliance — local model needed |
| **MTEB benchmark score** | Massive Text Embedding Benchmark — the standard leaderboard for comparing models across tasks |

### Common Model Options

| Model | Dimensions | Max Tokens | Best For |
|-------|-----------|------------|---------|
| `text-embedding-3-small` | 1536 | 8191 | General purpose, cost-efficient |
| `text-embedding-3-large` | 3072 | 8191 | Higher accuracy, 2× the cost |
| `text-embedding-ada-002` | 1536 | 8191 | Legacy OpenAI (use 3-small instead) |
| `sentence-transformers/all-MiniLM-L6-v2` | 384 | 256 | Fast, local, general purpose |
| `sentence-transformers/all-mpnet-base-v2` | 768 | 384 | Better quality, still local |
| `BAAI/bge-large-en-v1.5` | 1024 | 512 | Top open-source for retrieval (MTEB) |
| `intfloat/multilingual-e5-large` | 1024 | 512 | Arabic + English (UAE use case) |

### Quick Decision Guide

```
Need multilingual (Arabic)?    → intfloat/multilingual-e5-large
Privacy-sensitive data?        → Any local model (bge, MiniLM, mpnet)
Best retrieval quality?        → text-embedding-3-large or bge-large-en-v1.5
Cost-efficient & cloud ok?     → text-embedding-3-small
Fast prototyping?              → text-embedding-3-small (OpenAI, easy API)
Very long documents (>512 tok)?→ text-embedding-3-small or 3-large (8191 tokens)
```

## 5. Data Cleaning Before Generating Embeddings

Raw text from PDFs, web scrapes, or databases is noisy. Poor input → poor embeddings. Clean before embedding.

```python
import re

def clean_for_embedding(text: str) -> str:
    # 1. Collapse newlines and excessive whitespace
    #    PDFs often have hard line-breaks mid-sentence: "mutual\nfund" → "mutual fund"
    text = text.replace("\n", " ")
    text = re.sub(r"\s+", " ", text)   # collapse multiple spaces/tabs

    # 2. Strip leading/trailing whitespace
    text = text.strip()

    # 3. Remove non-printable / control characters
    text = re.sub(r"[\x00-\x1f\x7f]", "", text)

    # 4. Normalise Unicode (e.g. curly quotes → straight quotes)
    import unicodedata
    text = unicodedata.normalize("NFKC", text)

    # 5. Remove repeated punctuation (e.g. "......" → "...")
    text = re.sub(r"([!?.]){2,}", r"\1", text)

    # 6. Optional: lowercase (depends on model — most modern models are case-insensitive)
    # text = text.lower()

    return text


# Example — raw PDF extraction
raw = "  ENBD\nIslamic\nEquity Fund   \n\nThe fund invests in   Shariah‑compliant\nUAE equities.  "
clean = clean_for_embedding(raw)
print(repr(clean))
# → 'ENBD Islamic Equity Fund The fund invests in Shariah‑compliant UAE equities.'
```

### Additional Cleaning Patterns

```python
def clean_for_embedding_extended(text: str) -> str:
    text = text.replace("\n", " ")
    text = re.sub(r"\s+", " ", text).strip()

    # Remove URLs (often not useful for semantic content)
    text = re.sub(r"https?://\S+", "", text)

    # Remove email addresses
    text = re.sub(r"\S+@\S+\.\S+", "", text)

    # Remove page numbers (e.g. "Page 3 of 12" or "- 3 -")
    text = re.sub(r"(page\s+\d+\s+of\s+\d+|-\s*\d+\s*-)", "", text, flags=re.IGNORECASE)

    # Collapse again after removals
    text = re.sub(r"\s+", " ", text).strip()

    return text
```

### Chunking — Split Long Documents Before Embedding

Most embedding models have a token limit (512–8192 tokens). Long documents must be split into chunks.

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,       # target chunk size in characters
    chunk_overlap=50,     # overlap to preserve context across chunk boundaries
    separators=["\n\n", "\n", ". ", " ", ""],   # try to split on natural boundaries
)

raw_doc = "..."   # long fund prospectus text
chunks = splitter.split_text(clean_for_embedding(raw_doc))
# Now embed each chunk individually
embeddings = [embed(chunk) for chunk in chunks]
```

### Cost Estimation for a Batch of Documents

```python
import tiktoken

def estimate_embedding_cost(
    texts: list[str],
    model: str = "text-embedding-3-small",
    price_per_million: float = 0.02,   # USD per 1M tokens
) -> dict:
    """
    Estimate the cost of embedding a list of texts.

    Pricing (as of 2026):
      text-embedding-3-small: $0.020 per 1M tokens
      text-embedding-3-large: $0.130 per 1M tokens
      text-embedding-ada-002: $0.100 per 1M tokens
    """
    enc = tiktoken.get_encoding("cl100k_base")

    total_tokens = sum(len(enc.encode(text)) for text in texts)
    cost_usd = (total_tokens / 1_000_000) * price_per_million

    return {
        "num_documents": len(texts),
        "total_tokens": total_tokens,
        "avg_tokens_per_doc": total_tokens / len(texts),
        "price_per_million": price_per_million,
        "estimated_cost_usd": round(cost_usd, 6),
    }


# Example: embedding 500 mutual fund fact sheets
fund_docs = [
    "ENBD Islamic Equity Fund invests in Shariah-compliant UAE equities targeting long-term capital growth.",
    "Franklin UAE Bond Fund provides exposure to UAE sovereign and corporate fixed income securities.",
    # ... 498 more documents
]

result = estimate_embedding_cost(
    texts=fund_docs,
    model="text-embedding-3-small",
    price_per_million=0.02,
)

print(f"Documents:        {result['num_documents']:,}")
print(f"Total tokens:     {result['total_tokens']:,}")
print(f"Avg tokens/doc:   {result['avg_tokens_per_doc']:.1f}")
print(f"Estimated cost:   ${result['estimated_cost_usd']:.4f}")

# Example output:
# Documents:        500
# Total tokens:     87,340
# Avg tokens/doc:   174.7
# Estimated cost:   $0.0017
```

### Check a Single Document Won't Exceed Model Limits

```python
import tiktoken

def check_token_limit(text: str, max_tokens: int = 8191) -> tuple[int, bool]:
    enc = tiktoken.get_encoding("cl100k_base")
    count = len(enc.encode(text))
    fits = count <= max_tokens
    return count, fits

long_doc = "..."   # a large fund prospectus

token_count, fits = check_token_limit(long_doc)
if not fits:
    print(f"Document too long: {token_count} tokens — needs chunking before embedding")
else:
    print(f"OK: {token_count} tokens")
```

### Full Pre-Flight Workflow

```python
import tiktoken
from openai import OpenAI

client = OpenAI()
enc = tiktoken.get_encoding("cl100k_base")

PRICE_PER_MILLION = 0.02   # text-embedding-3-small
MAX_TOKENS = 8191

def embed_with_preflight(texts: list[str]) -> list[list[float]]:
    # 1. Count tokens and estimate cost
    token_counts = [len(enc.encode(t)) for t in texts]
    total_tokens = sum(token_counts)
    estimated_cost = (total_tokens / 1_000_000) * PRICE_PER_MILLION

    print(f"Total tokens:   {total_tokens:,}")
    print(f"Estimated cost: ${estimated_cost:.6f}")

    # 2. Guard: reject any document over the model's limit
    oversized = [(i, c) for i, c in enumerate(token_counts) if c > MAX_TOKENS]
    if oversized:
        raise ValueError(f"Documents exceed token limit: {oversized}")

    # 3. Embed in batches of 100 (OpenAI recommends batching for throughput)
    all_embeddings = []
    batch_size = 100
    for i in range(0, len(texts), batch_size):
        batch = texts[i : i + batch_size]
        response = client.embeddings.create(
            input=batch,
            model="text-embedding-3-small",
        )
        all_embeddings.extend([item.embedding for item in response.data])

    return all_embeddings
```

## Summary

| Concept | Key Point |
|---------|-----------|
| Embedding | Dense vector representing meaning; similar text → nearby vectors |
| Cosine similarity | Primary metric for text; range −1 to 1; higher = more similar |
| Semantic search | Embed query + docs; return nearest by cosine similarity |
| Clustering | k-means on embeddings groups semantically similar items |
| Recommendations | Nearest neighbours in embedding space |
| Anomaly detection | Items far from cluster centroid are outliers |
| Diversity (MMR) | Balance relevance and dissimilarity when selecting a set |
| Classification | Embed label descriptions; classify by nearest label |
| Model selection | Consider: task type, language, token limit, cost, privacy, MTEB score |
| Data cleaning | Replace `\n`, collapse whitespace, strip control chars, chunk long docs |
| Cost estimation | Use tiktoken before calling the API; `cl100k_base` for OpenAI models |
