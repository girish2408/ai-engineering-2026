## What Is RAG?

RAG (Retrieval-Augmented Generation) is a pattern that gives an LLM access to knowledge it was not trained on — your own documents, databases, or real-time data — by retrieving relevant content at query time and including it in the prompt.

Without RAG, an LLM answers from its training data only. It cannot know about your internal documents, recent events, or proprietary data. It may hallucinate answers when asked about things it doesn't know.

With RAG, the model answers from *retrieved evidence*. The answer is grounded in your actual documents, not a statistical guess.

```
Without RAG:  User question → LLM → answer (from training data, may hallucinate)

With RAG:     User question → retrieve relevant chunks from your docs
                           → question + chunks → LLM → grounded answer
```

---

## The RAG Question Answering Pipeline

The pipeline has three stages. The first runs once per document (preparation). The last two run once per user query.

```
┌─────────────────────────────────────────────────────┐
│  STAGE 1: PREPARE  (once per document)               │
│  Load → Split → Embed → Store in vector DB           │
└─────────────────────────────────────────────────────┘
                          │ (done once, reused for all queries)
                          ▼
┌─────────────────────────────────────────────────────┐
│  STAGE 2: SEARCH  (once per query)                   │
│  Embed question → rank chunks by similarity          │
└─────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────┐
│  STAGE 3: ASK  (once per query)                      │
│  question + top chunks → LLM → answer                │
└─────────────────────────────────────────────────────┘
```

## Stage 1 — Prepare the Document *(once per document)*

### 1a. Load the Document into LangChain Documents

LangChain provides loaders for every common document format. A loader reads a file and returns a list of `Document` objects, each with `.page_content` (the text) and `.metadata` (source, page number, etc.).

```python
from langchain_community.document_loaders import (
    PyPDFLoader,
    TextLoader,
    CSVLoader,
    UnstructuredWordDocumentLoader,
    WebBaseLoader,
)

# PDF — each page becomes one Document
loader = PyPDFLoader("enbd_fund_prospectus.pdf")
docs = loader.load()
print(f"Loaded {len(docs)} pages")
print(docs[0].page_content[:200])     # text of page 1
print(docs[0].metadata)               # {'source': 'enbd_fund_prospectus.pdf', 'page': 0}

# Plain text
loader = TextLoader("fund_description.txt")
docs = loader.load()

# Web page
loader = WebBaseLoader("https://example.com/fund-factsheet")
docs = loader.load()

# CSV — each row becomes one Document
loader = CSVLoader("fund_nav_history.csv", source_column="fund_name")
docs = loader.load()
```

---

### 1b. Split the Documents into Chunks

LLMs have token limits. A 200-page PDF cannot fit in a single prompt. Splitting breaks documents into smaller, overlapping chunks so each chunk fits in context and related content stays together.

**Why overlap?** If a sentence spans the boundary between two chunks, overlap ensures it appears in full in at least one of them.

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,        # max characters per chunk (~125 tokens)
    chunk_overlap=50,      # characters shared between adjacent chunks
    separators=["\n\n", "\n", ". ", " ", ""],   # split on natural boundaries first
)

chunks = splitter.split_documents(docs)
print(f"Split into {len(chunks)} chunks")
print(chunks[0].page_content)
print(chunks[0].metadata)   # inherits source and page from the parent document
```

**Choosing chunk size:**

| Chunk size | Good for | Trade-off |
|------------|---------|-----------|
| 200–300 chars | Precise fact retrieval | May cut off context |
| 500–800 chars | General Q&A | Balanced |
| 1000–1500 chars | Summarisation, long-form | More noise in retrieved chunks |

---

### 1c. Embed the Chunks into Numeric Vectors

Each chunk is converted into a fixed-length vector by an embedding model. Chunks with similar meaning will have vectors that are close together in the vector space.

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

# Embed a single string
vector = embeddings.embed_query("What is the NAV of the ENBD Islamic Fund?")
print(len(vector))      # 1536 dimensions
print(vector[:5])       # [0.021, -0.087, 0.034, ...]

# Embed a batch of chunks (more efficient)
texts = [chunk.page_content for chunk in chunks]
vectors = embeddings.embed_documents(texts)
print(f"Embedded {len(vectors)} chunks, each {len(vectors[0])} dimensions")
```

---

### 1d. Save the Chunks and Embeddings into a Vector Database

A vector database stores the embeddings alongside the original text. At query time it can rapidly find the nearest vectors to any given query vector — this is the core operation that makes retrieval fast at scale.

```python
# Example using Qdrant (in-memory for dev, server for prod)
from langchain_qdrant import QdrantVectorStore
from qdrant_client import QdrantClient

# In-memory (dev / testing)
client = QdrantClient(":memory:")
vectorstore = QdrantVectorStore.from_documents(
    documents=chunks,
    embedding=embeddings,
    location=":memory:",
    collection_name="enbd_funds",
)

# Persistent local (file on disk)
vectorstore = QdrantVectorStore.from_documents(
    documents=chunks,
    embedding=embeddings,
    path="./qdrant_data",
    collection_name="enbd_funds",
)

# Remote Qdrant Cloud
vectorstore = QdrantVectorStore.from_documents(
    documents=chunks,
    embedding=embeddings,
    url="https://your-cluster.qdrant.io",
    api_key="your-qdrant-api-key",
    collection_name="enbd_funds",
)
```

### Vector Database Options

The vector database is the storage and search layer of a RAG system. Choosing one depends on scale, infrastructure, and whether you need a dedicated vector DB or want to add vector search to an existing database.

#### Dedicated Vector Databases

**Qdrant**
Open-source, written in Rust. Available as in-memory, local file, or cloud. First-class LangChain integration. Great for production RAG at any scale.
```python
from langchain_qdrant import QdrantVectorStore
# supports: cosine, dot product, euclidean
# supports: filtering by metadata, named vectors, hybrid search
```

**Pinecone**
Fully managed cloud vector database. No infrastructure to run. Handles billions of vectors. Good when you want zero ops overhead and need to scale fast.
```python
from langchain_pinecone import PineconeVectorStore
from pinecone import Pinecone

pc = Pinecone(api_key="your-api-key")
index = pc.Index("enbd-funds")
vectorstore = PineconeVectorStore(index=index, embedding=embeddings)
```

**Milvus**
Open-source, designed for billion-scale vectors. Can be run locally (Milvus Lite), self-hosted (Docker), or as a managed cloud service (Zilliz Cloud). Better for very large datasets than Qdrant.
```python
from langchain_milvus import Milvus

vectorstore = Milvus.from_documents(
    documents=chunks,
    embedding=embeddings,
    connection_args={"uri": "http://localhost:19530"},
    collection_name="enbd_funds",
)
```

#### Adding Vector Search to Existing Databases

You don't always need a dedicated vector database. These options let you add vector search to infrastructure you already run.

**pgvector (PostgreSQL)**
Extension that adds a `vector` column type and similarity search operators to PostgreSQL. Ideal if you already use Postgres — your vectors live alongside your relational data.
```python
from langchain_postgres import PGVector

vectorstore = PGVector.from_documents(
    documents=chunks,
    embedding=embeddings,
    connection="postgresql+psycopg://user:password@localhost:5432/mydb",
    collection_name="enbd_funds",
)
# Vectors stored in a postgres table — queryable with SQL or LangChain
```

**MongoDB Atlas Vector Search**
MongoDB's cloud offering includes vector search as a native feature. Good if your application already uses MongoDB for documents and you want vector search without a second database.
```python
from langchain_mongodb import MongoDBAtlasVectorSearch
from pymongo import MongoClient

client = MongoClient("mongodb+srv://...")
collection = client["mydb"]["fund_chunks"]
vectorstore = MongoDBAtlasVectorSearch(
    collection=collection,
    embedding=embeddings,
    index_name="vector_index",
)
```

**Elasticsearch**
Elasticsearch 8+ supports dense vector fields and approximate nearest-neighbour search (HNSW). Good if you already run Elasticsearch for full-text search and want to add semantic search.
```python
from langchain_elasticsearch import ElasticsearchStore

vectorstore = ElasticsearchStore.from_documents(
    documents=chunks,
    embedding=embeddings,
    es_url="http://localhost:9200",
    index_name="enbd-funds",
)
```

#### Quick Comparison

| Database | Type | Best for | Hosting |
|----------|------|---------|---------|
| Qdrant | Dedicated vector DB | Production RAG, great LangChain support | Local, Docker, Cloud |
| Pinecone | Managed vector DB | Zero-ops, large scale | Cloud only |
| Milvus | Dedicated vector DB | Billion-scale vectors | Local, Docker, Zilliz Cloud |
| pgvector (Postgres) | Extension | Already on Postgres, co-locate data | Self-hosted or managed |
| MongoDB Atlas | Document + vector | Already on MongoDB | Cloud only |
| Elasticsearch | Search + vector | Already on ES, hybrid keyword+semantic | Self-hosted or Cloud |

## Stage 2 — Search *(once per query)*

### 2a. Embed the User Question

The same embedding model used to embed the chunks is used to embed the query. This is essential — both query and chunks must live in the same vector space to compare them.

```python
query = "What is the minimum investment for the ENBD Islamic Equity Fund?"
query_vector = embeddings.embed_query(query)
# Returns a 1536-dim vector representing the meaning of this question
```

### 2b. Rank Chunks by Similarity to the Question

The vector database finds the chunks whose embeddings are nearest to the query embedding. "Nearest" is measured by cosine similarity — the smaller the angle between two vectors, the more similar their meaning.

```python
# LangChain retriever — wraps the similarity search
retriever = vectorstore.as_retriever(
    search_type="similarity",    # cosine similarity
    search_kwargs={"k": 4},      # return the top 4 most similar chunks
)

relevant_chunks = retriever.invoke(query)

for i, chunk in enumerate(relevant_chunks):
    print(f"\n--- Chunk {i+1} ---")
    print(chunk.page_content)
    print(f"Source: {chunk.metadata.get('source')}, Page: {chunk.metadata.get('page')}")
```

**Retriever options:**

```python
# Basic similarity — top k by cosine score
retriever = vectorstore.as_retriever(search_kwargs={"k": 4})

# Similarity with a score threshold — only return chunks above a minimum score
retriever = vectorstore.as_retriever(
    search_type="similarity_score_threshold",
    search_kwargs={"score_threshold": 0.75, "k": 6},
)

# MMR (Max Marginal Relevance) — balances relevance and diversity
# Avoids returning 4 nearly-identical chunks
retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={"k": 4, "fetch_k": 20, "lambda_mult": 0.5},
)
```

## Stage 3 — Ask *(once per query)*

### 3a. Insert the Question and Most Relevant Chunks into a Message to GPT

The retrieved chunks become the **context** in the prompt. The LLM uses only this context to answer — it is instructed not to use outside knowledge, which prevents hallucination on your domain.

```python
from langchain_openai import ChatOpenAI
from langchain.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

llm = ChatOpenAI(model="gpt-4o", temperature=0)

prompt = ChatPromptTemplate.from_template("""
You are a helpful assistant for ENBD wealth management.
Answer the question using ONLY the context provided below.
If the answer is not in the context, say "I don't have that information in the provided documents."
Do not use any knowledge outside the context.

Context:
{context}

Question: {question}

Answer:
""")

def format_docs(docs):
    return "\n\n---\n\n".join(doc.page_content for doc in docs)

# LCEL chain: question → retrieve → format → prompt → LLM → string
rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | llm
    | StrOutputParser()
)
```

### 3b. Return the GPT Answer

```python
answer = rag_chain.invoke("What is the minimum investment for the ENBD Islamic Equity Fund?")
print(answer)
# → "The minimum investment for the ENBD Islamic Equity Fund is AED 10,000
#    for retail investors and AED 500,000 for institutional investors,
#    as stated in the fund prospectus."
```

## Full End-to-End RAG Pipeline

Putting all three stages together in a single script:

```python
from langchain_community.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_qdrant import QdrantVectorStore
from langchain.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

# ── STAGE 1: PREPARE ──────────────────────────────────────────────────────────

# 1a. Load
loader = PyPDFLoader("enbd_fund_prospectus.pdf")
docs = loader.load()

# 1b. Split
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split_documents(docs)

# 1c. Embed
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

# 1d. Store
vectorstore = QdrantVectorStore.from_documents(
    documents=chunks,
    embedding=embeddings,
    location=":memory:",
    collection_name="enbd_funds",
)

# ── STAGE 2 & 3: SEARCH + ASK (per query) ─────────────────────────────────────

retriever = vectorstore.as_retriever(search_kwargs={"k": 4})
llm = ChatOpenAI(model="gpt-4o", temperature=0)

prompt = ChatPromptTemplate.from_template("""
Answer the question using ONLY the context below.
If the answer is not in the context, say "I don't have that information."

Context:
{context}

Question: {question}
""")

def format_docs(docs):
    return "\n\n---\n\n".join(doc.page_content for doc in docs)

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | llm
    | StrOutputParser()
)

# Ask questions
questions = [
    "What is the minimum investment for the ENBD Islamic Equity Fund?",
    "What are the annual management fees?",
    "What is the fund's investment strategy?",
]

for q in questions:
    print(f"\nQ: {q}")
    print(f"A: {rag_chain.invoke(q)}")
```

## Why RAG Reduces Hallucination

Without RAG, the LLM answers from parametric memory (what it learned during training). When asked about specific fund data it was never trained on, it either says "I don't know" or invents a plausible-sounding but wrong answer.

With RAG, the prompt explicitly contains the relevant text from your documents. The system prompt instructs the model to answer *only from the context*. If the answer isn't in the retrieved chunks, the model says so — rather than fabricating.

```
Prompt structure:
  [System: answer only from context, do not use outside knowledge]
  [Context: retrieved chunk 1, chunk 2, chunk 3, chunk 4]
  [User question]
  → [Grounded answer]
```

## Summary

| Stage | Step | What happens | Code pattern |
|-------|------|-------------|--------------|
| **Prepare** | Load | File → LangChain Documents | `PyPDFLoader`, `TextLoader` |
| | Split | Documents → Chunks | `RecursiveCharacterTextSplitter` |
| | Embed | Chunks → Vectors | `OpenAIEmbeddings.embed_documents()` |
| | Store | Vectors → Vector DB | `QdrantVectorStore.from_documents()` |
| **Search** | Embed query | Question → Vector | `embeddings.embed_query()` |
| | Retrieve | Query vector → Top k chunks | `retriever.invoke(query)` |
| **Ask** | Prompt | Question + chunks → LLM | `ChatPromptTemplate` + LCEL chain |
| | Answer | LLM → grounded string | `StrOutputParser()` |
